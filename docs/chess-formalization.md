# チェス部分の形式化

原論文は、なんか「将棋およびチェスにおいて双方連続王手の千日手が成立しないことの証明」
第3版（2024年3月9日）、第6節、pp.12–14。本形式化の底本は原論文である。
チェスについては、それ以前にRavi Fernandoが自然言語による議論を公開している（[調査記録](novelty-review.md)）。
原稿での説明は[論文](../paper/main.tex)の「チェスの形式化」の節にある。

## 現在の成立範囲

`MPC.Chess` は将棋モデルから独立した8×8盤の基礎である。
局面・手・利き・王手・有限手順の独立基礎に加え、通常手と特殊手の局所条件、
盤面と権利の更新、玉配置の保存、周期性による捕獲・昇格・pawn移動の排除、
周期的連続王手によるcastling排除、玉の不動性と王手駒の分類、第6節の王手発生ライン・交差点・
図3の分類と候補の排除を経て、**チェスの不可能性定理`MPC.Chess.mutual_perpetual_check_impossible`を
証明した。** 正の長さの合法な手順で、毎手相手玉を王手し、盤上配置と手番が初期状態へ戻るものは存在しない。
玉の固定・無捕獲・無pawn移動・王手発生ライン・交差点・図3の性質は仮定せず導出する。
手データの存在と、`LegalMove`による局所的な合法性は区別する。
標準初期局面からの到達可能性や競技運営規則は、この局所条件に含めない。

| 宣言 | 意味と境界 |
|---|---|
| `MPC.Chess.Pos` | 各座標が0～7。第1成分がfile、第2成分がrank |
| `Color.forward` | Whiteはrank正方向、Blackは負方向 |
| `Position` | 盤上配置、手番、4個のcastling rights、en-passant target。持駒なし |
| `Promotion` | queen・rook・bishop・knightのいずれか。枚数上限は課していない |
| `Move` | 通常移動（捕獲や昇格を含み得る）、en passant、castlingのデータ |
| `applyMove` | 合法性とは独立した盤面・手番・権利・en-passant targetの更新 |
| `PseudoLegal` | 移動元・移動先、移動方向・経路、昇格、特殊手の条件。最終自玉安全は別 |
| `LegalMove` | 移動前の玉配置整合性、`PseudoLegal`、更新後の自玉安全 |
| `LegalTransition` | ある玉位置での`LegalMove`と、移動後が`applyMove`に一致すること |
| `Between` / `pathClear` | 整数座標上の開線分に属する盤内マスがすべて空。両端を除く |
| `attacks` | 6駒種の方向・距離・遮蔽の判定。攻撃元の存在と移動の合法性は要求しない |
| `inCheck` | 対象の相手色の実駒によるattack witness。対象の玉の存在は別条件 |
| `KingsWellPlaced` | 各色の玉が指定位置に存在し、同色の玉が他にない |
| `MoveTrace.Follows` | 外から与えた一手関係を、全手に要求する |
| `MoveTrace.EveryMoveChecksOpponent` | 移動前の手番の相手玉を、移動後に王手する |
| `MoveTrace.BoardTurnPeriodic` | 最初と最後の盤上配置と手番が一致する |

ポーンのattackは斜め1マスであり、前方への非捕獲移動とは区別する。
ナイトは両色とも8方向、queenは縦横斜めの長距離を認める。
king・knight・pawnのattackは途中の占有に依存しない。
rook・bishop・queenでは途中マスの占有だけを調べる。
ピンされた駒もattackを持つが、その駒が動けるとは限らない。
これらの区別は[FIDE Laws of Chess, Article 3](https://handbook.fide.com/chapter/e012023)
との対応に必要である。自玉の安全・捕獲・特殊手の条件は遷移層で扱う。

`attacks_mono` は空マス保存による利きの保存を証明する。
`inCheck_mono` はさらに王手駒が同じ位置・同じ内容で残ることを要求する。
攻撃駒まで除去する場合は王手保存を結論しない。
`KingsWellPlaced.positions_unique` は同じ盤面の玉位置関数の一意性であり、
手順の異なる状態間で玉位置が固定されるという主張ではない。

## 局所的な移動条件と保存定理

`MPC.Chess.Move`と`MPC.Chess.LegalMove`は次を分離する。

| FIDEの対応条文 | Leanでの条件・更新 |
|---|---|
| 1.4.1、3.1、3.2–3.6、3.8.1 | `DestinationAvailable`で自駒・玉の捕獲を禁止。非pawnの通常移動は`attacks`で判定 |
| 3.7.1–3.7.3 | `PawnMovement`で空マスへの前進と斜めの捕獲を分岐。2マス前進は開始rankと空経路を要求 |
| 3.7.3.1–3.7.3.2 | target、開始rank、斜めの利き、隣接する相手pawnを確認。`enPassantCaptured`のpawnを除去 |
| 3.7.3.3–3.7.3.5 | `PromotionAllowed`で最終rankへのpawn移動に昇格を必須化。それ以外の昇格を禁止 |
| 3.8.2 | `CastleAllowed`で権利、homeの自玉・rook、間の空経路、開始・通過・着地マスへの利きを確認 |
| 3.9.2 | `LegalMove.ownKingSafe`で特殊手も含む更新後の実盤面の自玉安全を要求 |

アンパッサン情報は通常の2マス前進で設定し、その他の手では消去する。
`nextEnPassant_eq_some_iff`が直前の手との対応を証明する。
castling rightsは玉の移動、homeのrookの移動・捕獲で失われ、
`applyMove_castlingRights_no_gain`により復活しない。
手順を途中から与える場合、最初の権利・targetはその局面以前の履歴に関する
入力であり、その履歴の到達可能性までここで証明したとは扱わない。

`KingsWellPlaced.applyMove`は、移動前の配置と`PseudoLegal`だけから、
`kingPositionsAfter`が移動後の実盤面に一致することを証明する。
通常手ではsourceの玉だけを移し、en passantでは非玉の捕獲位置を消し、
castlingでは玉とrookの2回の盤面更新を合成する。
移動後の配置整合性を`LegalMove`の仮定に置いていない。
これは一手の整合性保存であり、玉の位置が手順全体で一定だという定理ではない。

`LegalMove`は初期配置からの到達可能性を要求しない。したがって、任意の
盤面におけるこの述語の成立を、その盤面の履歴全体が合法だという意味に
拡張しない。玉の不動性には、後述する周期的連続王手の条件を用いる。

## 周期性からの還元

`MPC.Chess.Material`は盤面上の整数の加重和`Board.weightedSum`と、
次の3量を定義する。空マスは0を寄与し、駒の個体識別や枚数上限を使わない。

| 量 | 定義 | 一手の性質 |
|---|---|---|
| `Board.pieceCount` | 占有マスごとに1 | `PseudoLegal`で非増加。通常捕獲とen passantで厳密に減少 |
| `Board.pawnCount` | pawnごとに1 | `PseudoLegal`で非増加。昇格で厳密に減少 |
| `Board.pawnProgress` | White pawnのrank、Black pawnの7−rankの総和 | 捕獲・昇格を除いた手では非減少。pawn移動で厳密に増加 |

`weightedSum_relocate`は通常更新、`weightedSum_erase`は1マスの除去の
加法的な収支を与える。en passantは除去と移動、castlingは2回の移動に分解する。
昇格はpawnの進行量を減らし得るので、進行量の単調性より先に昇格を除外する。

`MPC.Chess.PeriodicReduction`では、`FollowsLegalMoves`と
`BoardTurnPeriodic`から次の順に証明する。

1. 駒数が全状態で等しいため、通常手の着地点は空で、en passantはない。
2. pawn数が全状態で等しいため、昇格はない。
3. 上記の結果からpawn進行量も全状態で等しく、pawnは移動しない。

これらには連続王手や玉位置の固定を要求しない。状態対は任意であり、
先頭・最終状態、同じ状態、逆順の組も含む。長さ0でも成立する。

さらに全状態の玉配置整合性と`EveryMoveChecksOpponent`を置くと、
正の長さの手順では各状態の手番側の玉が王手されている。
`inCheck_turn_of_periodic_checks`の先頭状態では、最後の手の王手を使い、
両端の盤面一致と玉位置の一意性で対象位置を合わせる。
これは周期境界での位置一致であり、途中の玉位置の固定性ではない。
`CastleAllowed`は開始時の非王手を要求するため、castlingも排除できる。

最終的に`ordinary_nonPawn_move_of_periodic_checks`は各手について、
非pawnの通常手・昇格なし・空の着地点・異なるendpointと、
手番側の移動元の実駒およびその移動先への`attacks`を与える。
Part 3のこの結論では通常のking移動を排除しない。捕獲なし・特殊手なしを追加の仮定にせず、
盤上配置と手番だけの反復条件から導いており、権利やtargetの両端一致は使わない。

## 玉の不動性と王手駒の分類

`MPC.Chess.KingGeometry`と`MPC.Chess.KingImmobility`は、原論文の命題2.2を
8×8盤とチェスの局所遷移について証明する。将棋側の宣言はimportしない。

- 合法手後の自玉安全を状態ごとの実在玉に対応づける。正の長さの周期手順では、
  先頭状態の相手玉の安全も最後の合法手から導く。初期安全を追加仮定にしない。
- 玉同士の利きは対称なので、各状態で両玉は隣接しない。玉自身は直接王手できず、
  玉の移動が王手するなら、別の駒の新しいslide攻撃が移動元を通っている。
  `new_attack_source_between`は一手の更新からこの遮蔽除去を取り出す。
- `kingMove_alignment`は、玉移動の前には両玉が同じfile・rank・diagonal上にあり、
  後にはどの方向でも整列しないことを示す。整数座標の4方向の直線条件、
  1マス移動と両玉の非隣接性を使い、近似計算や図の目視に依存しない。
- 玉以外の手では両玉位置が保たれるため、失われた整列は回復しない。
  盤面の周期性と玉位置関数の一意性から、玉移動を排除する。

`kingPositions_eq_of_periodic_checks`は任意の状態対`i j`で玉位置関数が等しいことを
結論する。長さ0も含み、固定位置を入力するモデルへ置き換えてはいない。
`ordinary_nonKing_nonPawn_move_of_periodic_checks`はPart 3の各手のwitnessに
「移動駒はkingでない」を追加する。

`MPC.Chess.CheckerReduction`は、第6節冒頭のpawn・knightによる王手排除を証明する。
王手駒は相手の応手で動かず、捕獲もされず、対象玉も移動しない。
king・pawn・knightの利きは途中の占有に依存しないため、この王手は応手後も残り、
自玉安全に反する。最後の状態の王手には、周期境界を使って最初の応手を適用する。

`checking_piece_is_slider_of_periodic_checks`は正の長さの手順の任意の状態・対象色について、
存在と所有者を持つ王手witnessの駒種をqueen・rook・bishopに限定する。
`not_pawn_check_of_periodic_checks`と`not_knight_check_of_periodic_checks`が個別の否定を、
`exists_slider_checker_of_periodic_checks`が各手番側の玉を攻撃する実駒を与える。
王手駒の一意性やknightの移動そのものの禁止は主張しない。
これらは合法遷移・玉配置整合性・毎手の王手・盤面と手番の周期性からの帰結であり、
玉不動性・初期安全・王手駒の駒種を新たな仮定として追加していない。

## 睨みと一手の王手分類

`MPC.Chess.TraceGlare`は、原論文の定義2.1・2.3に対応する。
`Move.Touches`は、通常手のsource/destination、en passantの捕獲マス、
castlingで動くkingとrookの両端を列挙する。castlingの位置は移動前の手番で決まる。
`ImmovableAt`は「初期状態で占有され、どの手でも触れられない位置」とする。
内容が全状態で同じというだけでは、不動とは定義しない。同じ内容で上書きされる
生の盤面更新でも、着地点はtouchされた位置になる。
`immovable_board_eq`は合法遷移から内容の保存を導く。
`immovableAt_kingPos_of_periodic_checks`は、Part4の帰結から両玉の不動性を導く。

`strippedBoard`は対象の駒と不動駒を現在の盤面に残し、他を取り除く。
`GlaresAtEnemyKing`は現在存在する駒が、この盤面で相手玉の指定位置を攻撃する条件である。
空盤面での利きに置き換えず、不動の遮蔽物を残す。玉の実在は別途
`KingsWellPlaced`によって保証する。`glares_of_attacks`により実際の利きは睨みを含意するが、
動く遮蔽物を取り除いて初めて睨みが成立する場合があるため、その逆は成り立たない。

`MPC.Chess.GlaringMove`の盤面補題は周期性を使わず、昇格しない通常更新を扱う。
`hasDestinationChecker`は着地点の実駒による王手、`hasUnblockedChecker`は前後で
同じ位置・同じ内容を保つ非endpointの実駒が、同じ対象に新たに利く条件である。
後者はsourceが経路内、destinationが経路外であることも含む。
`inCheck_relocate_iff_destination_or_unblocked`は、sourceに駒が存在し、両端が異なり、
移動前には指定対象への王手がないとき、移動後の王手を両者の**包含的な論理和**に分ける。
両方を満たす二重王手を排除しない。単に非着地点にある継続中の王手は、後者に含まない。

`between_of_between_tail`は8方向の線上の途中点から終点までの開区間が、元の開区間内に
あることを示す。これと盤面更新の局所性から、遮蔽除去による王手があればsourceから
対象までの実盤面経路が既に空だったことを導く。sourceの駒が別の盤面で対象に利くなら、
実盤面でも既に王手となり、移動前非王手と矛盾する。これが補題2.5の証明である。

| 原論文 | 公開定理（`MoveTrace`名前空間） | 帰結 |
|---|---|---|
| 補題2.4 | `unblockedChecker_of_destination_not_glares` | 睨まない位置への移動で王手をかける手は遮蔽除去を伴う |
| 補題2.5 | `not_unblockedChecker_of_source_glares` | 睨む駒の移動は遮蔽除去による王手を伴わない |
| 補題2.6 | `destination_glares_of_source_glares` | 睨む駒は移動後にも相手玉を睨む |

手順上の定理は合法遷移、玉配置整合性、毎手の相手玉への王手、盤面・手番の周期性を
仮定する。通常手への還元はPart3、玉位置の前後一致と移動前の相手玉の安全はPart4から
得るため、初期安全や全手順の不動性を追加仮定にしていない。
明示した通常手のindexが手順の非空性も保証する。一般の6種類の駒を扱う盤面補題と、
周期的手順での駒種還元は区別している。

原論文は「開き王手でない王手」を直接王手と呼ぶ。
本実装の着地点checkerだけでは開き王手の併存を否定しないため、その名称で定義していない。
睨む駒の移動については`destinationChecker_of_source_glares`と補題2.5を合わせ、
着地点checkerの存在と遮蔽除去checkerの不在をともに得られる。
補題2.8への逆向きは次節の個数議論で補う。命題3.3の期間内保持は後の節で扱う。定義6.1・補題6.2は後の王手発生ラインの節で扱う。

## 周期的な睨み分類の保存

`MPC.Chess.PeriodicGlare`は原論文の補題2.8を、駒の個体識別を導入せずに証明する。
`nonGlaringSquares`は、現在占有され、相手玉を睨まない位置の有限集合である。
空マスや、遮蔽のため実際には王手していないが睨んでいる駒は数えない。

`glares_congr`は、同じマスに同じ駒があり、玉位置が同じなら、異なる状態でも睨みが
同値となることを示す。合法遷移から不動マスの内容を保持し、動く遮蔽物は両状態の
`strippedBoard`から取り除かれるためである。これには周期性や連続王手を要求しないが、
玉位置の一致を明示する。単なる実盤面上の王手の継続を主張する補題ではない。

局所的な個数補題では、昇格しない通常手について、玉位置の前後一致と
「sourceで睨むならdestinationでも睨む」という含意から、非睨み駒数が増えないことを示す。
移動後のdestinationを移動前のsourceに戻し、他の位置をそのままにする写像が単射になる。
非睨みから睨みへの移動では、sourceがその像から失われるため、個数が厳密に減る。
これらの補題は周期性を仮定せず、具体的な合法prefixにも適用できる。

周期的連続王手では、Part3・4から通常手への還元と玉位置の固定を、Part5aの補題2.6から
睨みの順方向保存を得る。盤面と手番が初期状態に戻ると有限集合も元に戻るため、
単調非増加な個数はすべての状態で等しくなる。厳密な減少は不可能となり、補題2.8を得る。
追加の不動性・個数一定・睨み分類の仮定を置いていない。

| 公開定理（`MoveTrace`名前空間） | 結論 |
|---|---|
| `nonGlaringSquares_card_eq_of_periodic_checks` | 任意の状態対で非睨み駒数が一致する |
| `glares_source_of_destination_of_periodic_checks` | 補題2.8：移動後に睨むなら移動前にも睨む |
| `glares_destination_iff_source_of_periodic_checks` | 動く駒の移動前後で睨み分類が同値 |
| `glares_other_iff_of_periodic_checks` | 非endpointのマスでも睨み分類が同値 |
| `unblockedChecker_iff_not_source_glares_of_periodic_checks` | 遮蔽除去checkerの存在 iff 移動前の駒が睨まない |
| `destinationChecker_iff_source_glares_of_periodic_checks` | 着地点checkerの存在 iff 移動前の駒が睨む |

最後の二つにより、この周期的連続王手の条件下では二重王手の併存も排除される。
Part5aの局所的な分類は引き続き包含的論理和であり、一般の合法手の二重王手は禁止しない。
また、睨む駒が動かないとは主張しない。移動前後の分類が同じであることと、
ある期間内に同じ位置を保つことは別の性質であり、後者は次節のPart5cで別途導く。
補題2.9の非捕獲は、チェスではPart3の全捕獲排除が既に与える、より強い帰結に含まれる。
駒打ちの補題2.7はチェスには導入しない。

## 滞在区間のwitness保持と着地点のライン

`MPC.Chess.OpenableLine`と`MPC.Chess.OpenableLineCyclic`は、原論文の命題3.3・系3.4を扱う。
対象は、相手玉を睨まない駒が通常手で到着するマスAである。
駒がAに留まる間、別の自駒Qが位置Bから相手玉を睨み、そのラインの内部にAがあることを示す。
Qを不動駒として仮定せず、対象期間の内容保存・非touchを結論として導く。

まず局所的な`line_witness_persists`では、終点状態にQが存在して睨み、Qがsliderであり、
Aがライン内部で区間中占有されることから、Qの存在と睨みを区間の始点まで遡る。
Bへの到着は、Part5bに対応する「睨む着地点の駒は実際に王手する」という性質に反する。
Aが経路を塞いでいるからである。またBからの移動は直後のBを空にしてしまう。
これにより各状態の同じ駒内容に加え、区間のどの手もBに触れないことを証明する。
この局所定理には周期性を要求せず、`OrdinaryMoves`、玉位置一定、
`GlaringDestinationsCheck`を明示的な外付け条件として渡す。周期的連続王手への適用時には
これらをPart3〜5bから導き、手順型のフィールドや主結果の追加仮定にはしない。

`departure_of_occupied_of_periodic`は、占有状態以降の最初のtouchを選ぶ。
全捕獲が排除されるため、この手はAへの到着ではなくAからの離脱となる。
その離脱が非睨み駒の移動なら、Part5bの分類から遮蔽除去checker Qを得る。
Qは同じ側のqueen/rook/bishopであり、その経路にAが入る。

`openable_line_cyclic_of_periodic_checks`は、到着後の最初の離脱を**仮定せず導く**。
同じ周期内にtouchがあればそこまでを使い、なければAの駒を最終状態から初期状態へ運び、
周期の前半で離脱を探す。Qについても前半のwitnessを初期状態から最終状態へ移し、
局所的な保持定理で到着まで遡る。必要な反復は盤面・手番のみであり、
castling権利やen-passant情報の反復は要求しない。

状態の閉じた区間を`cyclicBetween`、区間内で実行される手を`cyclicStepBetween`とする。
後者は離脱手を含めない。例えば5状態の3→2という滞在は全状態indexを覆うが、
手2（状態2→3）は滞在を終了させる離脱なので保持対象ではない。
両端の状態が区間に入るという条件だけで、手の所属を判定していない。
最終定理は、区間中Aが到着直後の駒内容を保ち、Bが同じQを保って睨むことに加え、
区間内のどの手もA・Bのどちらにも触れないことを明示する。
全手順にわたる不動性を結論する定理ではない。

系3.4の敵側ラインには、移動前の実際の王手駒XをPart4から取り出す。
捕獲は禁止され、玉位置も動かないので、着地点がXの経路になければ移動後も王手が続き、
自玉安全に反する。`destination_between_checker_of_periodic_checks`がこの内部所属を示す。
`openable_destination_lines_of_periodic_checks`は自駒Qと敵駒Xの存在・所有者・盤面時点・睨みを
明示し、到着点が両ラインの内部にあることを導く。原論文は敵checkerの捕獲を許す端点付きの
結論を述べるが、チェスではPart3の捕獲排除により両方とも厳密な内部所属になる。
Xの存在や次の離脱、Qの位置保持を新たな仮定にしていない。

## 王手発生ラインと異なる半直線への移動

`MPC.Chess.CheckingRayGeometry`、`CheckingRay`、`CheckingRayMoves`は定義6.1・補題6.2を扱う。
`RayDirection`はqueenの8方向を表し、`OnRay king d q`は玉位置を原点とする半直線上の
盤内のマス（原点を除く）への所属である。`onRay_iff_positive_steps`が、方向ベクトルの
正の整数倍との同値を保証する。原点を除くのは、王手駒・移動endpointは固定玉のマスと
異なるためである。この盤内述語を、次節で原点・盤外・非格子点を含む有理座標へ拡張する。
`rayDistance`は同じ半直線上のマスを比較するためのL1距離であり、
後続の交差点列（A1・A2）の構成を完了したことは意味しない。

`MoveTrace.CheckingRay tr king owner d`は、ある状態でその半直線上に実在する
`owner.opponent`の駒が、実盤面上で`king`を攻撃することを要求する。
対象玉の存在はこの述語に含めず、手順への適用時に`KingsWellPlaced`を使う。
また原点は明示的に渡し、適用時にPart4の玉位置一定から`kp 0 owner`にそろえる。
睨みのwitnessだけでは定義6.1を満たさず、実際の王手の状態が必要である。

着地点の所属は次のように示す。移動側の玉については、移動前の敵checkerの経路を
着地点が塞ぐことを使う。相手玉については、移動後に睨む駒なら着地点の実際の王手を使う。
睨まない駒ならPart5cで次の離脱と滞在中の同じ駒内容を得て、その離脱による実際の
遮蔽除去checkerを取り出す。周期境界の前後いずれも扱い、将来のcheckerの存在を仮定しない。
移動元の所属には`source_is_destination_of_periodic`を使う。どの手もそのマスへ
到着しないと仮定すると占有指標が単調非増加になり、盤面の反復と移動元の消失が矛盾する。
この到着は同じ周期内の前後どちらにあってもよく、駒の個体識別を要求しない。

`not_same_ray_of_periodic_checks`が同じ半直線内の移動を排除する。
非玉・非pawnの移動が同じqueen半直線上にあるとき、knightの移動方向とは合わず、
移動経路は空である。一方、遮蔽の位置を同じ半直線上で変えるには、王手駒を
飛び越す必要がある。直接の着地点checkerの場合も、空の着地点・空の移動経路・
移動後の王手経路から移動前の相手玉への王手が導かれ、周期性から得た安全性に反する。
捕獲禁止、玉固定、実際の王手witness、安全性はいずれも既存の手順条件から導く。

`every_move_between_distinct_checkingRays`は任意の手indexについて、通常手への還元と、
任意の`owner : Color`に対する異なる2方向の王手発生ラインへのendpoint所属を結論する。
追加条件は置かず、`FollowsLegalMoves`、`KingsWellPlaced`、`EveryMoveChecksOpponent`、
`BoardTurnPeriodic`を使う。長さ正は手indexの存在から得る。特殊手を手順型から削除せず、
Part3・4の排除定理を再利用する。交点順序には以下の構成を使い、補題6.4・図3の分類は後の節で扱う。

## 有理座標の半直線と交差点

`MPC.Chess.RationalRay`は`PlanePoint := ℚ × ℚ`を導入し、`Pos.toPlane`で盤内のマスを
埋め込む。この埋め込みは単射である。`OnRationalRay`は8方向ベクトルの**非負**の
有理数倍で表される半直線であり、原点を含む。`onRationalRay_toPlane_iff`は、
盤内での所属が「原点と一致する、または既存の`OnRay`を満たす」と同値であることを示す。
正のパラメータに限れば従来の盤内述語とそのまま同値になる。旧定義は変更しない。
`rayParameter`は同じ半直線上の位置を一意に表し、始点の移動・向きの反転に伴う
所属条件を証明する。これだけでは交差点の有限な順序列は構成しない。

`MPC.Chess.RayIntersection`は2方向の行列式と始点の変位から交点のパラメータを計算する。
非平行なら支持直線の方程式を解き、両パラメータが非負の場合に限り半直線の交点を得る。
`nonparallelIntersection_eq_some_iff`は計算結果と両半直線への所属を同値にし、
`rationalRay_intersection_unique`は非平行の場合の一意性を示す。

**`nonparallelIntersection = none`を無条件に「交点なし」と読んではならない。**
行列式が0の場合もこの計算器は`none`を返すためである。
`parallel_rays_intersect_iff`が平行の場合を別途分類する。支持直線が異なれば交点はなく、
同方向で同一直線上なら重なり、逆方向なら始点が向き合う（または一致する）場合に
両始点を含む線分で重なる。始点が一致する逆方向の半直線では原点だけが共通になる。
全ての王手発生ラインが非平行だとは仮定も結論もしていない。

`MPC.Chess.CheckingCrossing`の`MoveTrace.CheckingCrossing`は、両玉それぞれの
実際の王手発生ラインに属する有理点を表す。平行な重なりと原点も定義から排除しない。
非平行計算器で得た点からこの交差点への接続を証明する。
`every_move_between_checkingCrossings`はPart5dを再利用し、任意の手の両endpointが
交差点であり、両玉それぞれの同じ有理半直線上にはないことを導く。
移動endpointが原点に一致しないことも既存の正方向の所属から導き、追加前提にしない。

定義6.3への接続は有理座標モデルであり、実平面全体との全面的な対応は未完了である。
有限集合とA1/A2への順序づけは以下のモジュールで構成する。補題6.4の両主張への接続は以下で示す。
平行な重なりの排除は次節で手順条件から導く。

## 両玉の直線と平行な重なりの排除

`MPC.Chess.KingLineGeometry`は`Pos.collinear`を座標の外積の等式で定義する。
8方向の整数パラメータと厳密な途中点の順序を対応づけ、両玉の直線上に着地した場合、
他方の玉または既存のラインの駒が、その先の利きを遮る幾何補題を証明する。
この幾何層は手順条件に依存しない。

`MPC.Chess.KingLineExclusion`は原論文命題3.5・3.6をチェスについて証明する。
`openable_destination_off_kingLine_of_periodic_checks`は、移動前に相手玉を睨まない駒の
着地点が両玉の直線上にないことを示す。Part5cの期間内保持から、着地後の味方の
睨み駒がすでに移動前に存在したことを使う。原論文注意3.2に相当する条件は、
証明済みの玉の不動性と、`strippedBoard`がその玉を残すことから導く。
直線上に着地したと仮定すると、味方の睨み駒または相手玉が実際の移動前の王手を遮り、矛盾する。

`checker_off_kingLine_of_periodic_checks`は、正の長さの周期的連続王手で、
任意の状態・玉所有者・実在checkerについて両玉の直線上にないことを証明する。
応手の着地点がcheckerと玉の間にあることと命題3.5から、応手の駒による王手が必要になる。
しかしその王手の経路も玉または元のcheckerに遮られる。
原論文の捕獲を繰り返す議論について、チェス側ではPart3ですでに全捕獲を排除しているので、
応手の一手で矛盾を得る。最終状態は周期境界を使って先頭の応手に接続する。

`MPC.Chess.CheckingRaySeparation`はこの結果を有理半直線へ接続する。
`checkingRay_offset_ne_zero_of_periodic_checks`により、王手発生ラインの支持直線は
両玉を通る直線と一致しない。したがって他方の玉からの平行な半直線とは共通点を持たない。
**平行で互いに交わらない王手発生ラインは排除していない。**
`checkingCrossing_iff_nonparallelIntersection_of_periodic_checks`は、全交差点がPart6aの
非平行計算器で得られることを同値として示す。交差点がどちらの玉の原点でもないことも導く。
この同値を有限集合の構成と距離順序へ接続する。

既存の半直線・交差点・手順の定義を変更せず、非共線性・非平行性・不動性を
手順の新しい仮定に追加していない。命題3.5の一手の定理は手indexから長さ正を得る。
任意の状態・ライン・交差点の定理では`0 < tr.len`を明示する。長さ0では正しく玉を置き、
全手条件と周期性を満たしても、両玉の直線上に王手駒と重なる半直線が存在し得る。

## 交差点の有限集合と距離順序

`MPC.Chess.CheckingCrossingSet`は、両玉それぞれの8方向を組み合わせ、実際の王手witnessを
持つ方向対の非平行交点を`checkingCrossings`へ集める。集合なので同じ点は重複して数えず、
要素数は最大64である。任意の手順では平行な重なりを列挙しないため、この計算だけで
定義6.3の全交差点を得たとは言えない。
`mem_checkingCrossings_iff_of_periodic_checks`は、正の長さと既存の合法手・玉配置・
毎手の王手・盤面と手番の周期性から、有限集合への所属と`CheckingCrossing`の同値を導く。
非平行性を追加仮定にはせず、Part6b1の排除定理を使う。これにより全交差点の有限性と、
各通常手のsource・destinationがこの集合に含まれることも得る。

`MPC.Chess.CheckingCrossingOrder`は固定した玉と方向について、集合を半直線で絞り込み、
その`rayParameter`を`rayCrossingParameters`へ集める。`checkingCrossingAt`はこれを
昇順に並べ、有限indexから点を返す。全ての所属点が列挙され、異なるindexでパラメータと
距離が厳密に増加する。`planeTaxicabDistance`を有理数上のマンハッタン距離として定義し、
固定した半直線上ではパラメータとの大小の一致を証明した。異なる方向間の距離比較や
ユークリッド距離の数値計算は必要ない。通常の正の周期手順では、原点の排除から全パラメータが正となる。

原論文補題6.4の導入にあるA1・A2は、それぞれ0番目・1番目の点
`firstCheckingCrossing`・`secondCheckingCrossing`に対応する。定義の引数には
それぞれ「少なくとも1点」「少なくとも2点」の個数条件を明示する。
`firstCheckingCrossing_spec`はA1が最小であること、`secondCheckingCrossing_spec`は
A2がA1より遠く、A1を除いた中で最小であることを示す。1点以下の集合からA2を選ばず、
既定値を交差点として補うこともしない。全ての王手発生ラインに2点あることを以下で
盤内witnessとして示し、その後で有限集合の個数と王手駒のA2に対する順序へ接続する。

## 王手駒より遠くない2交差点の構成

`MPC.Chess.CheckingCrossingWitness`は、補題6.4(1)の盤面上のwitnessを構成する。
`arrival_piece_departs_of_periodic`は、通常手の到着先から、同じ駒内容・同じ側による
再出発が周期内に存在することを示す。最初のtouchと捕獲の排除を使い、再出発のindexが
到着より前になる周期境界も扱う。この補題に王手や睨みの条件は必要ない。
個体識別子を導入せず、盤面上の駒内容の一致を述べる。

`board_eq_of_not_mem_checkingCrossings`は、交差点集合の外では任意の状態間で
盤面内容が一致することを示す。全ての移動endpointが交差点に属する既存定理から導き、
不動性の仮定は追加しない。空のマスも含む。逆に盤面内容が変わった位置は
`mem_checkingCrossings_of_board_ne`によって交差点となる。

`checker_two_crossings_of_periodic_checks`は、任意の状態・所有者・実際の王手駒に対し、
異なる盤内交差点A・Bを与える。Aは王手駒と玉の開区間にあり、Bは同じ開区間か王手駒の位置にある。
最初の応手のdestinationをAとする。王手駒自身が交差点ならそれをBに選ぶ。
そうでなければその駒は保持される。Aからの再出発後にも自玉は安全なので、
王手駒の経路には別の占有位置Bが必要となる。Bは元の王手局面では空だったため、
内容変化から交差点への所属が得られる。Aは再出発直後には空なので、AとBは異なる。

任意の状態の王手を扱う定理には正の長さを明示し、最終状態では先頭の応手を使用する。
王手駒の位置保持は「その位置が交差点でない」場合に導くもので、全駒の不動性ではない。
`checkingRay_two_crossings_of_periodic_checks`は、各王手発生ライン上の異なる2交差点へ
特殊化する。これらのwitnessを選択済みのA1・A2と同一視せず、次節で有理パラメータの
個数・順序へ接続する。補題6.4(2)も以下で証明する。図3の分類・最終不可能性定理は後の節で扱う。

## 第2交差点と王手駒の順序

`MPC.Chess.CheckerCrossingOrder`は補題6.4(1)を完成させる。
`rayCrossingParameters_card_two_le_of_distinct`は同じ半直線上の異なる2点から
異なるパラメータを得る。`secondCheckingCrossing_parameter_le_of_two`は、その2点が
同じ上限以下ならA2もその上限以下であることを示す。witnessの順序は任意であり、
witnessそのものがA1・A2であることや、盤内の格子点であることは要求しない。

`rayCrossingParameters_card_two_le_of_periodic_checks`は正の長さの合法な周期的連続王手と
実際の王手発生ラインから、`rayCrossingParameters`の要素数が2以上であることを導く。
個数は新しい仮定ではなく、A2の定義へ渡す証明として生成される。
`checker_parameter_ge_second_of_periodic_checks`は、任意の状態にいる王手駒の位置を
2点の上限として使う。`checker_eq_or_beyond_second_of_periodic_checks`により、
王手駒はA2に一致するか、同じ半直線上でA2より厳密に遠いことが得られる。
距離順序は有理数上の`planeTaxicabDistance`で述べ、固定半直線上のパラメータ順序と一致する。

先頭・最終状態を含む任意の状態、両所有者、全8方向を扱う。A2は有理平面上の点のままで、
盤面へ丸めない。王手駒の所属するラインの`CheckingRay`条件は、その駒の存在・所有者・
利きと証明済みの玉位置固定性から構成できる。長さ正と既存の手順条件は維持する。
A2にいる駒が手順中に移動するという(2)の結論は、この順序定理だけからは主張しない。

## 第2交差点にいる王手駒の出発

`MPC.Chess.SecondCrossingMoves`は補題6.4(2)を証明する。
`crossing_before_second_eq_first`はA2より手前の交差点がA1に限られることを示す。
`checker_not_immovable_at_second_of_periodic_checks`では、A2の王手駒が不動だと仮定する。
応手の合駒の着地点Aは交差点で、A2の手前にあるためA1と一致する。周期性からAの再出発があり、
その直後の自玉安全には残った王手駒を遮る別の占有位置Bが必要となる。Bは元の王手時には空なので、
内容変化から交差点となり、これもA1と一致する。しかしAは再出発直後に空となるため矛盾する。

`occupied_piece_departs_of_not_immovable`は、任意の状態の占有位置が不動でない場合、
周期順で最初のtouchが通常手による出発になることを示す。王手・睨み・玉配置は仮定しない。
`checker_at_second_departs_of_periodic_checks`はこれをA2の王手駒へ適用し、出発手・移動先・
出発直前の同じ駒内容を返す。さらに出発までの`cyclicBetween`内での内容保持と、
`cyclicStepBetween`内で一度もtouchされないことを保証する。単に同じ位置から同種の別の駒が
出発するという結論にはせず、個体識別子なしで元の駒の滞在から接続する。

先頭・最終状態、即時出発と周期境界をまたぐ出発、両所有者・8方向を一般形で扱う。
A2を選ぶ個数条件は前節から導き、長さ正・合法手・玉配置・毎手王手・盤面/手番の周期性を維持する。
「合駒の再出発よりも先」という順序を公開APIの結論には追加していない。
図3の分類と最終不可能性定理は後の節で扱う。

## 両玉の直線による開半平面と8方向

`MPC.Chess.KingHalfPlane`は定義3.7の開半平面を、有理座標の外積の符号で表す。
`HalfPlaneSide`の正負はKからLへ向かう基準に依存し、両玉を交換すると反転する。
境界直線上の点はどちらにも入らず、境界外の点は一意な側に入る。
`halfPlaneDirections`は8方向のうち、正のパラメータでその側へ進む方向の有限集合である。
任意の境界上の始点からの正の半直線と所属が一致し、KとLが異なる場合、
各側の方向数は3または4となる。実数の角度値や盤端による切り詰めは使わない。
同一原点、パラメータ0、境界上の方向について同じ結論を主張しない。

`MPC.Chess.CheckingRayHalfPlane`は、正の長さ・合法手・玉配置・毎手王手・盤面/手番の周期性から、
既存の王手半直線のking-line排除を使って側の一意性を導く。共通交差点では、白玉から黒玉へ向かう
同じ基準で点と両側の半直線を分類する。黒玉から出る半直線にも同じ基準を用いるため、
局所的な正負を取り違えない。所属・交点数を手順の追加仮定にはしない。

これは定義6.5に先立つ方向数の事実を支える基礎である。角度順の第1〜第4方向の順位付けと、
各玉の王手発生ラインを2方向へ制限する議論は次節で扱う。
対称性による図3の4候補の網羅性は後の節で扱う。

## 定義6.5の角度順位と2方向への制限

`MPC.Chess.RayAngleRank`は定義6.5の「なす角」を実数の角度ではなく、相手玉への変位との
内積`rayDot`と外積`rayOffset`の比較で扱う。`kingRayRank o r d`は、`o`から`r`へ向かう方向と
`d`のなす角が(0°,45°]、(45°,90°]、(90°,135°]、(135°,180°)のどれに入るかを1〜4で返す。
45°・90°・135°ちょうどは小さい側の閉区間に入れ、原論文の`l₁`〜`l₄`の区分に一致させる。
両玉の直線上の方向は順位付けの対象外であり、定理は開半平面の所属を仮定する。

同じ開半平面の異なる方向は異なる順位をもつ（`kingRayRank_injOn`）。
`kingRayRank_add_le_four`は原論文の三角形の議論で、`o`からの半直線と`r`からの非平行な
半直線が両原点以外で交わるなら、両者の順位の和は4以下である。交わる角は45°以上なので、
両玉でなす角の和は135°以下になる。したがって順位4の半直線はどれとも交わらず、
順位3の半直線は順位1とだけ交わり得る。平行な重なりでは和が5になる例があり、
非平行性の仮定を外さない。

`MPC.Chess.CheckingRayRank`は、正の長さ・合法手・玉配置・毎手王手・盤面/手番の周期性から、
補題6.4(1)の2交差点、Part7aの側の一意性、Part6b1の平行な重なりの排除を組み合わせる。
各王手発生ライン上の2交差点は、同じ側にある相手玉の異なる王手発生ラインと交わるため、
`checkingRay_rank_le_two_of_periodic_checks`により全王手発生ラインの順位は2以下となる
（原論文の`l₃`・`l₄`・`k₃`・`k₄`は王手発生ラインでない）。
`halfPlane_checkingRays_of_periodic_checks`は、ある半平面に王手発生ラインが一つでもあれば、
その半平面の各玉の王手発生ラインはちょうど順位1・2の2本であり、両玉の組の4交点が
すべて盤内のマスになることを証明する。順位・側・交点の存在を手順の仮定に追加しない。
順位は各玉から相手玉へ向かう方向を基準とし、側は与えた色の玉から相手玉へ向かう向きで測る。

図3の具体的な候補（両玉の相対位置と4本の方向）への網羅的な分類は後の節で扱う。

## 格子の対称性（フレーム）

原論文は図3の候補を「平行移動や回転、反転により一致するもの」を除いて数える。
`MPC.Chess.LatticeFrame`は、原点を固定する格子の8つの対称性を、座標の交換と各座標の符号反転の
組合せとして定義する。`apply`は有理座標の変位に、`dir`は8方向に作用し、`dir_vector`により両者は整合する。
`neg`は点対称で、相手玉から見た同じ配置を表す。`dir_opposite`によりフレームは方向の反転と可換である。`det`は回転で1、反転で-1である。
平行移動は原点の玉として明示し、盤面の範囲はフレームの外で扱う。

`rayPoint_dir`・`onRay_dir_iff`は、フレームで写した方向の半直線を、標準座標の半直線をフレームで
写したものとして表す。他方の玉が`K + F(w)`にあるとき、`rayOffset_dir`は外積に`det`を掛け、
`rayDot_dir`は内積を保つ。したがって`kingRayRank_dir`・`kingRayRank_dir_swap`により、
両玉からの角度順位は標準座標の値で計算でき、`mem_halfPlaneDirections_dir`により
半平面の所属は`det`と側の符号の積だけで変わる。`mem_halfPlaneDirections_opposite`は
逆向きの方向が反対側に入ることを述べる。実数の角度や回転行列は使わない。

標準座標の存在、盤内の距離、1つの半平面の分類は次節、図3の4候補はその次の節で扱う。

## 1つの半平面の図3分類

`MPC.Chess.Figure3Geometry`は盤面の条件を加える。`exists_frame_canonical`は、異なる2マスについて
相手玉を標準座標`(a, b)`（`0 ≤ b ≤ a`、`0 < a`）に置くフレームを与え、`abs_le_seven_of_frame`は
盤内の2マスの差が標準座標でも各成分7以下であることを示す。`frame_crossing_eq`は両玉からの半直線上の
盤内のマスを、標準座標の連立方程式に直す。`side_sign_mul_det_of_north`は、標準座標の北が与えた側に
入るとき、側の符号とフレームの向きが一致することを述べる。

`halfPlane_figure3`は、Part7b2の4本（順位1・2の方向）と盤内の4交点を入力とする。
`b = 0`（両玉が軸上）では両玉の順位2の方向がともに標準座標の北、`b = a`（対角線上）ではともに北西となり、
平行な2本は交わらないので矛盾する。`0 < b < a`では4本は自玉側の北東・北、相手玉側の西・北西に定まり、
交点は`(b, b)`・`((a+b)/2, (a+b)/2)`・`(0, b)`・`(0, a+b)`となる。第2の交点が格子点であることから
`a + b`は偶数、第4の交点が盤内であることから`a + b ≤ 7`であり、`(a, b)`は`(3,1)`・`(5,1)`・`(4,2)`の
いずれかに限る（図3の上段）。結論には盤内のマス`K + F(0, a+b)`も含め、両半平面の組合せに使う。

## 図3の4候補

`MPC.Chess.Figure3Candidates`は前節を手順へ接続する。毎手王手から王手発生ラインが存在し
（`exists_checkingRay_of_periodic_checks`）、その側について一方の玉からのフレームを取る。
標準座標の北がその側に入らない場合は、相手玉から見た点対称のフレーム`neg`に取り替える。
`halfPlane_candidate_of_periodic_checks`はPart7b2とPart7c2を合成し、その半平面の両玉の
王手発生ラインを標準座標の北東・北と西・北西に特定する。

`figure3_candidates_of_periodic_checks`は全王手発生ラインを特徴付ける。反対側の半平面にも
王手発生ラインがある場合（`both`）、相手玉から点対称のフレームで同じ分類を適用すると、自玉側の
東・南東と相手玉側の南・南西が加わる。両側の端の交点`K + F(0, a+b)`と`K + F(a, -a)`がともに盤内に
あることから`2a + b ≤ 7`となり、`(a, b) = (3, 1)`に限る。したがって両玉の位置と王手発生ラインは、
フレームと平行移動を除いて、片側だけの`(3,1)`・`(5,1)`・`(4,2)`（図3上段）と両側の`(3,1)`（図3下段）の
4候補に限る。各色の側の取り方や片側の候補を手順の仮定にしない。候補の排除は次節以降で扱う。

## 図3上段の候補の排除

`MPC.Chess.Figure3Moves`は、原論文「上側の3つの候補では、補題6.2の条件をみたすような移動は、
左図のAとBの間をknightで移動する場合のみである」を証明する。`StepShape`は縦横斜めの直線とknightの
変位を絶対値で表した条件で、`stepShape_frame`によりフレームで不変である。
`move_stepShape_of_periodic_checks`は、Part3・4の玉・pawnの不動と`attacks`から、各手の変位が
`StepShape`を満たすことを導く。`crossing_northEast_west`などは上側の4交点の標準座標
`(b, b)`・`((a+b)/2, (a+b)/2)`・`(0, b)`・`(0, a+b)`を与える。

`false_of_upper_candidate`は、片側だけの候補で各手を補題6.2（Part5dの
`every_move_between_distinct_checkingRays`）により両玉それぞれ異なる王手発生ライン上の交差点の間の
移動に限り、標準座標の変位を調べる。`(5,1)`・`(4,2)`では移動が存在せず、`(3,1)`では
`A = (0, 1)`と`B = (2, 2)`の間の移動だけが残る。`false_of_two_square_moves`は、全手が2マスの間の
移動なら、最初の手で動いた駒の色と次の手番が食い違うことを示す（長さ1は手番の周期性で除く）。
`figure3_lower_candidate_of_periodic_checks`により、残るのは図3下段の候補だけである。

## 図3下段の候補の排除と主定理

`MPC.Chess.Impossibility`は原論文「下の候補では、例えば半直線LC上の駒PがLにある玉に王手を
かけているときを考える。補題6.4より、PはCにあり、しかもいずれCから別の位置に移動しなければならないが、
補題6.2の条件をみたすような移動は不可能である」を証明する。標準座標で`L = K + F(3, 1)`とし、
LCは`L`からの標準座標の南である。

`lowerRay_crossing_parameter`は、LC上の有理交差点が`L`からのパラメータ1と4の点、すなわち
`K + F(3, 0)`と`C = K + F(3, -3)`に限ることを示す（`frame_rational_crossing_eq`）。
有限集合の第1・第2交差点の仕様から、A2は`C`である。`false_of_lower_candidate`では、
LC上の王手駒について補題6.4(1)（`checker_parameter_ge_second_of_periodic_checks`）から
パラメータ4以上を得る。標準座標の北の遠い交差点`K + F(0, 4)`が盤内のマスであることと盤内の距離から
パラメータ4以下となり、王手駒は`C`にある。補題6.4(2)（`checker_at_second_departs_of_periodic_checks`）で
その駒は`C`から出発するが、補題6.2からその手の移動先は自玉側の南東・相手玉側の南以外の王手発生ラインの
交差点で、`crossing_east_southWest`・`not_crossing_*`を含む全組合せのどれも`C`から直線またはknightの
変位にない。

`mutual_perpetual_check_impossible`は、Part8aの下段候補への絞り込みとこの排除を合成した主定理である。
仮定は長さ正・合法手（`FollowsLegalMoves`）・玉配置・毎手王手・盤面と手番の周期性だけで、
castling rightsやen-passant targetの一致は要求しない。長さ0の手順は他の仮定をすべて満たすため、
長さ正は外せない。

## FIDEの同一局面と主定理の系

本モデルの`FIDESamePosition`は、手番と盤上配置に加え、白黒それぞれのキング側・クイーン側のcastling権利と、
手番側の合法手の集合（各手について、整合する玉配置での`LegalMove`が存在するか）を比較する。
たとえば白のナイトがg1を塞いでいても、白がキング側の権利を失えば局面を区別する（第9.2.3.2条）。
盤上配置・手番・権利が一致するとき、`FIDESamePosition.iff_legal_enPassant`により、判定は
始点・終点ごとの合法なen passant捕獲の有無の一致と同値になる（第9.2.3.1条）。
対象マスが記録されていても、唯一の捕獲候補が自玉を王手にさらすなら、その記録は判定に影響しない。
[FIDE Laws of Chess 第9.2.3条](https://handbook.fide.com/chapter/e012023)

`boardTurnPeriodic_of_fideSamePosition`は、
同一局面への復帰から盤上配置と手番の反復を導く。系
`mutual_perpetual_check_impossible_of_fideSamePosition`により、正の長さの合法な手順で毎手相手玉を王手し、
FIDEの意味で初期局面と同一の局面へ戻るものは存在しない。反復による引き分けの申し立てや
3回・5回反復の規定、50/75手規則、時計は不可能性の根拠に使わない。

## 再現と信頼性

固定済みの `lean-toolchain` と `lake-manifest.json` を使う。

```sh
./scripts/verify_chess.sh
./scripts/verify_phase6.sh --phase6-complete
```

前者は `MPC.Chess` と `MPC.Chess.Verification` を独立してビルドする。
後者は将棋側の全検証と既存API型・公理依存比較に加えてチェス検証も実行する。
`lake build` の既定rootと `MPC.lean` は将棋用のまま維持する。
チェス検証は、将棋宣言が環境に入らないこと、公開チェス宣言の依存公理が
Lean標準公理だけであること、公開289定理の期待する依存出力、主定理と系の正確な主張を確認する。
独自公理・証明の穴・`native_decide` は全ソース監査で禁止する。

回帰例は両色のpawn、knight全8方向、queen全8方向、遮蔽・遮蔽除去、
両端の占有、checkerの存在・所有者、空の対象位置、玉位置一意性、
長さ0と一手のデータを扱う。加えて通常捕獲、2マス前進、昇格先4種、
2マス前進直後のen passant、期限切れ・捕獲pawn不在、両色・両側のcastling、
権利喪失・経路占有・通過中の王手を検証する。
移動で自玉を王手にさらす通常手、およびen passantによるrookの利きの開放を
`LegalMove`が拒否する例も含む。

還元の回帰例では、両色の通常捕獲・pawn捕獲・1/2マス前進・全4種の昇格・
捕獲昇格・en passant・両側のcastlingについて各量を計算する。
長さ0の手順は王手条件を空虚に満たし得るが、先頭の王手は結論できない。
また、現在の局所モデルで合法なcastlingから始まり、盤上配置と手番を戻す
8手の手順を両色について構成した。玉位置と権利は途中で変わり、
権利は両端でも異なる。この例は連続王手を満たさず、周期性だけから
castlingや玉移動を除外できないことを示す。
周期性を持たない王手の一手例では、先頭の自玉が王手されていないことも確認する。

玉不動性の回帰検証では、8方向の線上からの玉移動、移動後の非隣接条件を
欠いた場合の別の線への移動、盤端の玉の利きの対称性を確認する。
周期性を持たない局所合法手では玉の開き王手とpawn・knightの王手が可能であり、
連続王手を満たさない合法な4手周期では両色のknightが移動できる。
長さ0ではpawn・knightの王手を含む盤面も全手条件を空虚に満たすため、
王手駒の分類には正の長さが必要であることも固定する。

睨みの回帰検証は、両色・両側の特殊手footprint、不動の遮蔽物と動く遮蔽物、
検査対象の駒の保持、長さ0、同一内容の上書きと不動性の違いを扱う。
周期性を持たない合法な2手の連続王手では、最初の駒は睨みを保つが、次の駒は
睨まない位置から睨む位置へ移る。したがって補題2.6の逆には別途周期性の議論が必要である。
着地点のみの王手、遮蔽除去のみの王手、両者が併存する二重王手、継続中の王手も区別する。
8方向の経路の包含は、盤面端を含む任意の途中マスについて検証する。

周期的分類の回帰検証では、両色の合法prefixで非睨み駒数が3→3→2となることを計算し、
局所的な単調性・厳密減少補題を適用する。非endpointのqueenは、動く遮蔽物が経路に
入って実際の利きを失っても睨みを保つ。逆順の状態間でも一般の合同補題を適用する。
長さ0では不動マスが増えて同じ初期盤面の個数が4となる例と、全状態の個数保存を確認する。
玉が合法的に王手から逃れる一手では、残るrookの睨みが変わるため、合同補題の
玉位置一致の前提を取り除けないことも確認する。

期間内保持の回帰検証では、両色の合法な3手prefixを構成し、knightがrookのラインに
到着して留まる間、rookが実際には王手せず睨みを保つ例に局所保持定理を適用する。
連続王手を満たさない4手の合法なknight周期では、最初の離脱・非touchによる内容保持・
前後占有からの非touchを検証する。これらを周期的連続王手の実現例とは扱わない。
循環区間の通常・wrap・単一点・長さ0、最初/最後の手、全状態を覆っても離脱手を
含めないケース、最終/初期状態だけを結ぶ境界を確認する。8方向のqueen経路に
着地点を追加する遮蔽例では、純粋な更新補題の対偶を適用して着地点の所属を確認する。

王手発生ラインの回帰検証は、8方向の内部所属・順序・交差、原点の除外、反対の半直線、
非整列、盤端の7歩を扱う。両色で長さ0の実際の王手、攻撃駒不在・所有者不一致、
合法な手順で睨みだけが成立して実際の王手発生ラインにはならない例を確認する。
非周期の合法な王手では同じ半直線上の移動が可能であり、捕獲を許せば同じ半直線上で
新しい王手を作れる例も固定する。4手の非連続王手のknight周期には、全手indexで
移動元への別の到着を導く定理を適用する。周期的連続王手の実現例とは扱わない。

有理交点の回帰検証では、全ての非平行方向の組について既知の交点を復元し、
対角線の半整数交点・盤外交点・順序を入れ替えた計算・原点での交点・負のパラメータを確認する。
平行な支持直線の不交差、同方向の重なり、向き合う/離れる逆方向、原点だけの共通部分も扱う。
両色の長さ0の盤面で、実際の王手witnessを持つ交差点と非交差点を確認し、
盤内の王手発生ラインが半整数で交わる例にも接続定理を適用する。
これらの静的な例を、正の長さの合法な周期的連続王手の例とは扱わない。

両玉の直線の回帰検証は、8方向それぞれで遮蔽となる位置の2ケースを扱う。
両色の長さ0の盤面は、全手条件と周期性を満たしつつ、両玉の直線上で半直線が重なり、
玉の原点や非格子点も交差点になる。長さ正の前提を省けないことを固定する。
周期性を持たない合法な2手の連続王手では、直線上のcheckerと、そこへ着地する非睨みのknightを構成した。
別の合法な4手周期は、先頭/最終状態で直線上のrookが王手するが毎手王手を満たさない。
これらは各前提を省いた場合の具体例であり、すべての前提を満たす正の長さの周期の例ではない。

有限集合と順序の回帰検証では、両色の2交差点のA1/A2を実際に計算し、
交差点がない半直線・半整数の1交差点・盤外交差点も確認する。
同じ点を返す複数の方向対は1点にまとめる。長さ0の平行な重なりでは
`CheckingCrossing`が区間全体を含む一方、有限列挙は空となる例も固定し、
完全性定理の仮定を省略できないことを確認する。全8方向について
パラメータ順序と距離順序の一致を一般の有理数で扱う。

2交差点witnessの回帰検証では、王手を伴わない4手の合法なknight周期で、
両開始手番・全手indexの到着先からの再出発を確認する。再出発のindexは2手後（mod 4）であり、
先頭と最終手をまたぐケースも含む。一手だけの非周期の合法手順には再出発がない。
両色の長さ0の盤面では他の手順条件を満たしつつ交差点が1点だけとなり、
2交差点定理から長さ正を除けないことを固定する。全8方向の局所盤面で、
唯一の合駒がライン外へ移動すると保持されたqueenの王手が復活することも確認する。

A2への接続では、両色の2交差点を逆順にwitnessとして渡し、個数条件を生成して
A2の上界を得る。A2上とそれより遠い点の距離を計算し、任意の有理パラメータ・8方向でも
同じ上界定理を適用する。任意の状態の実際のcheckerから`CheckingRay`を構成し、
個数や不動性を追加前提にしない公開APIの利用例も検証する。従来の0点・1点・半整数・
盤外交差点・長さ0の検証を維持し、静的な例を正の周期的連続王手とは扱わない。

A2の出発の検証では、合法な4手knight周期で両開始手番・両所有者・全5状態の占有knightに
出発定理を適用し、そこまでの内容保持と非touchを確認する。最終状態からの出発が手0へ
戻ることも固定する。この例は毎手王手を満たさない。別の長さ0の盤面では、玉配置・遷移条件・

(2)の結論からも長さ正を除けないことを確認する。一般の有理交差点へのA1同定も検証する。

開半平面の回帰検証では、全8方向の軸・対角境界で各側3方向、斜めの非対角境界で各側4方向を
